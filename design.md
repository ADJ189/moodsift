# Moodsift design system

A portable record of the decisions that make Moodsift look like a product
rather than a generated template. Read this before adding or restyling a
surface. The implementation lives in `src/styles/` and `src/lib/appearance.ts`;
this file explains *why*.

## 1. The idea

**Cinematic utility.** Moodsift is a tool for choosing something to watch, not
a streaming service and not a landing-page demo. The interface should feel like
a well-made cinema programme: dark, quiet, typographic, and confident enough
not to decorate every surface.

One idea per screen:

| Screen | The one idea |
|---|---|
| Landing | "A few real titles, matched to you" — the sample card is the proof, the CTA is the action |
| Quiz | One question at a time, no chrome competing with the choice |
| Rating | Calibration, not a chore: familiar titles, five stars, move on |
| Results | The match and its reason; everything else is secondary |
| Search | Type a title or a person; grouped results, no modal maze |

## 2. Hard anti-slop rules

These are the defaults models converge on. Do not reintroduce them:

1. **No gradient headline text.** Headlines are solid `--text-primary`.
   `--gradient-match` is for meters and small data marks only.
2. **No eyebrow label above the H1.** Privacy and trust copy belongs after the
   CTA, in normal sentence case, not in mono caps floating above the title.
3. **No two-blob radial glow.** One restrained top-light per screen, plus the
   existing film grain. If a second glow is needed to make a surface legible,
   fix the surface instead.
4. **No default Inter.** The body face is **Manrope** (Sora for display).
   Inter survives only inside optional presets. Inter is the strongest
   "generated by a model" tell in a type stack.
5. **No default particle storm.** Decorative particles default to `subtle`.
   `interactive` is an explicit user choice, never the first impression.
6. **No uniform pill-and-card grid.** Cards have a clear hierarchy: artwork
   first, title, one match signal, actions on demand. Don't make every element
   the same radius, the same glow and the same weight.
7. **No bounce.** Motion is ease-out and short. `--ease-spring` is reserved for
   small state changes, never for page-level movement.
8. **No copy that oversells.** "Approximate weight-file size", "storage
   optimisation, not encryption", "may not be available". Honest limits are
   part of the brand.

## 3. Type

| Role | Default | Notes |
|---|---|---|
| Display | Sora Variable | Geometric, slightly technical; headings only |
| Body | Manrope Variable | Neutral with warmth; replaces Inter |
| Mono | System mono | Metadata, timestamps, diagnostics only |

Rules:

- Heading weight 600; tracking `-0.01em`; don't stack letter-spacing and
  uppercase for emphasis.
- Long-form copy maxes out around 60–70 characters (`--content-width` and
  local `max-width` do this).
- `text-wrap: balance` on the landing H1 only. Don't apply it to card titles.
- Font presets are curated ids, never arbitrary family strings or URLs.
  All faces are self-hosted through Fontsource; the default pair is imported
  statically, every other preset loads on demand.

## 4. Colour and surfaces

- Eight palettes, each with light and dark tokens (`palettes.css`). Components
  consume semantic names (`--surface`, `--text-secondary`, `--violet`), never
  literal hex values.
- Neutral canvas is warm in light mode (cream/paper), not cool white. Accent
  colours keep the identity; the neutral underneath is what makes it feel
  authored.
- Borders are low-contrast hairlines. Strong borders are for focus, selection
  and interactive affordances, not decoration.
- Shadows are soft and directional. Neon-style glow belongs only to the
  `neon-noir` design style, which is opt-in.
- Glass surfaces must become opaque under Reduced transparency.

## 5. Layout and density

- Content width: 920 / 1120 / 1320 px (`compact` / `comfortable` / `wide`).
- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48 px. Avoid one-off values.
- Radius: 8 / 14 / 20 px plus pills. Sharp and rounded shape presets remap the
  same tokens; components must not hard-code radii.
- Poster minimum: 150 / 200 / 250 px by preference.
- On phones the primary action must be visible without scrolling. The hero
  visual is hidden below 520 px so the CTA wins.

## 6. Motion

- `--dur-fast` 160 ms, `--dur-med` 320 ms, `--dur-slow` 560 ms; cinematic
  movement up to 640 ms and only for the hero / result reveal.
- Semantic reduced motion: big movement is removed, opacity and focus feedback
  remain. "Motion: Off always wins" over every card, style and search option.
- Hover lift is at most 4 px + 1.5 % scale. No parallax on text.
- Decorative canvas loops stop when leaving the landing screen.

## 7. Components

- **Title card:** artwork → title/year → match badge or meter → reason →
  actions on hover/focus (always visible on touch). Rating and watchlist are
  available without opening details.
- **Chips:** metadata only, not navigation. Keep them few and low-contrast.
- **Buttons:** one primary per view; quiet secondary; text buttons for
  dismissive actions. Minimum target 24 × 24 px (aim for 44 px on touch).
- **Settings:** a workspace with section tabs, scoped resets and presets that
  write ordinary preferences. Never a separate "theme mode" that bypasses the
  stored values.
- **Dialogs:** labelled, focus-trapped, Escape closes, restore focus to the
  trigger. No nested dialogs.

## 8. Accessibility is the floor

- WCAG AA contrast in every palette, light and dark, including high contrast.
- Keyboard operable everywhere; visible focus ring (`--focus-ring`).
- Screen-reader labels on icon-only controls; live regions for async results.
- Axe scans cover new settings sections, card types, design styles and search
  types.
- Forced-colors and 200 % text zoom must not create horizontal overflow.

## 9. What is intentionally optional

Card type, design style, search type, palette, font preset, density, text size,
motion, particles and transparency are **presentation only**. They must never
change what is searched, scored or stored, and must never override an
accessibility preference.
